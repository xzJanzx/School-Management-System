# SMS — Module 02 — Parent / Guardian
Status: COMPLETED

## Verification Principle
Verify real persistent behavior, not only source existence or mocked/in-memory behavior.

## Verification Gates

### Guardian Identity
Verify:
- Guardian ID is automatically generated
- Guardian ID is unique
- Guardian ID is immutable
- concurrent creation cannot duplicate Guardian IDs

### National ID
Verify:
- valid National ID accepted
- duplicate National ID is detected/protected
- approved duplicate-review behavior is respected

### Contact Data
Verify:
- required primary phone
- optional additional phone/email/address
- canContact
- preferred contact method

### StudentGuardian
Verify:
- one Student can have multiple Guardians
- one Guardian can have multiple Students
- relationship type is stored
- duplicate relationship is blocked
- existing Guardian can be reused

### Primary Guardian
Verify:
- one active Primary Guardian maximum per Student
- assigning a Primary Guardian works
- replacing Primary Guardian works
- previous primary relationship/history is preserved
- concurrent primary assignments cannot create two active primaries

### Lifecycle
Verify:
- active/inactive behavior
- linked Guardian cannot be hard-deleted destructively
- history remains intact

### Permissions
Attempt unauthorized sensitive Guardian modification.
Expected: Access Denied.

### Audit
Verify persistent audit records for:
- sensitive Guardian changes
- Guardian lifecycle changes
- relationship changes
- Primary Guardian changes
- duplicate override/review where applicable

Verify actor, action, entity, timestamp and old/new values or reason where required.

### Search / Profile
Verify:
- Guardian search
- Guardian Profile
- Student → Guardians
- Guardian → Students
- authorization prevents unauthorized exposure

### Database / Migration
Verify:
- formal migration exists and applies
- data persists after restart
- migration is safe/idempotent according to project rules
- existing Module 01 data remains intact

### Module 01 Regression
Verify at minimum:
- Student create/read/update
- Student search
- Student duplicate protection
- Student status/history
- Student audit
- Student documents/integration boundary

### Build / Quality
Run:
- tests
- lint
- type check
- production build

No unresolved compilation errors, required failing tests or critical security/data-integrity gaps.

## Gap-Fix Rule
For every failure:
1. identify exact requirement;
2. identify exact failure;
3. identify root cause;
4. apply minimum correction;
5. rerun affected tests;
6. rerun Module 02 suite;
7. rerun Module 01 regression;
8. rerun build/quality checks.

Do not rewrite unrelated modules.

## Completion
Verification is complete only when the required evidence and quality gates pass and identified gaps are resolved.
