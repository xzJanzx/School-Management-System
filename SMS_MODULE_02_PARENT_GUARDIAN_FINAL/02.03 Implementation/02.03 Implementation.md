## Guardian ID
Generate automatically.
It must be unique, permanent, immutable and concurrency-safe.

## National ID
Validate when supplied.
Protect against duplicates according to the approved review workflow.

## Relationship
Use the existing Student entity.
Represent Student ↔ Guardian explicitly.
Do not embed the whole Guardian domain into Student.

## Primary Guardian
At most one active Primary Guardian per Student.
Use transaction/database protection so concurrent requests cannot create two active primaries.
Preserve history when the primary changes.

## Existing Guardian Reuse
When the approved duplicate/review process establishes that a Guardian already exists, reuse that Guardian rather than creating a second master record.

## Delete Protection
Do not hard-delete a linked Guardian if doing so would destroy relationship/history integrity.

## Security
Enforce authorization server-side.
Never trust client-supplied role/permission headers.

## Audit
Persist sensitive Guardian operations and relationship/primary changes as required by the approved audit model.

## UI
