# SMS — Module 01 — Student Master Data
Status: APPROVED

## Purpose
Module 01 owns the permanent Student Master identity used by the rest of SMS.

Student is not Enrollment, Academic History, Transfer, Promotion, Guardian, or Academic Structure.

A student remains the same identity when the academic year, grade, class, enrollment, promotion, re-enrollment, or transfer changes.

## Permanent Identity
Student Number:
- automatically generated
- unique
- permanent
- immutable
- never reused

File Number:
- automatically generated
- unique
- permanent
- immutable
- never reused

national_id remains required.

## Master Data
The Student master record covers the approved student identity/personal information, including:
- names
- date of birth
- place of birth
- gender/type
- nationality
- religion where required
- national ID
- photo
- contact information
- address
- master status
- operational active flag
- status history

Approved status concepts:
- master_status: ACTIVE, INACTIVE, ARCHIVED, SUSPENDED
- is_active: operational field consumed by later modules

## Core Operations
- Create Student
- Get Student
- Update Student
- Search Students
- Get Student Profile
- Change Student Status
- Get Status History
- Check Possible Duplicate
- Review Possible Duplicate
- Authorized Duplicate Override

## Duplicate Protection
The system must detect possible duplicate students before creation.

A possible match:
1. blocks automatic creation;
2. enters Manual Review;
3. may be overridden only by an authorized user;
4. requires an explicit reason;
5. creates an auditable record.

Concurrency must not allow two permanent identities to be created for the same protected identity.

## Historical Integrity
A student referenced by academic history must not be physically deleted in a way that destroys historical records.

Promotion, transfer, re-enrollment and academic-year changes must not create a new Student identity.

## Guardian Boundary
Guardian is a separate entity.
A Student may have multiple Guardians.
A Guardian may relate to multiple Students.
The relationship is represented explicitly and is not reduced to a single guardian field on Student.

Module 01 integrates with Module 02 but does not own the Guardian master entity.

## Document Boundary
Student documents are associated with the Student.
Module 01 exposes the required integration/data boundary; it does not become a separate document-management system.

## Search
Approved search dimensions include:
- Student Number
- File Number
- name
- National ID

Additional filters may be exposed only when supported by the approved module contracts.

## Security and Audit
Sensitive Student operations require backend authorization.

Audit must cover sensitive operations, including creation, sensitive updates, status changes, duplicate review/override, and relationship changes where applicable. Audit evidence must preserve actor, action, entity, entity ID, timestamp and old/new values or reason where required.

## Non-Responsibilities
Module 01 does not own:
- annual Enrollment
- Academic Structure
- Transfer workflow
- Promotion workflow
- Guardian master entity
- unrelated future modules
