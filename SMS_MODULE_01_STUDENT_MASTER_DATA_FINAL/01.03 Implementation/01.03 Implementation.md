## Domain Rules
Student is the permanent person identity.

Do not merge:
Student / Enrollment / Guardian / StudentGuardian / Academic Structure / Transfer / Promotion.

Later modules reference Student; they do not create another Student identity.

## Security
Authorization must be enforced server-side.
Client-controlled roles or headers must never be trusted.

Sensitive changes require the appropriate permission.

## Audit
Record sensitive operations with sufficient actor/action/entity/time context and old/new values or reason where required.

## Data Integrity
Use real persistent storage and the project's approved migration mechanism.
Do not create a second database, ORM, migration system, authentication system, permission system, or audit system.

Use transaction-safe operations for multi-record changes.
Protect permanent identifiers under concurrency.

## Historical Integrity
Never create a new Student because of promotion, transfer, re-enrollment or academic-year change.
Do not physically delete a Student when that would destroy academic history.

## Completion
Do not claim completion while required build/tests fail or required business/security/audit rules are absent.
